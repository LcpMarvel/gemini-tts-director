# 导演方法

目标是让台词中的关系与动机听得见。不要默认把每句话加满情绪词和叹气；短句也可以没有风格提示。

## 先判断文本，再决定怎么演

这是宿主导演 Agent 的阅读判断，不是脚本按关键词分类，也不再调用另一个规划模型。先识别文体、谁在说话、叙述与台词的边界、双方是在轮流发言还是同时回应，以及用户要忠实朗读还是允许改编。信息足够就直接选择，关键角色关系不明时才询问。

| 文本与关系 | 通常采用 | 需要留意 |
| --- | --- | --- |
| 散文、说明、新闻、独白 | 单人朗读 | 引用别人的话也可能只是叙述，不必换声 |
| 小说、故事、广播剧 | 按场景组合旁白和角色表演 | 不把“他说”“众人笑”直接当作台词或音效；不把整部作品硬分成一种模式 |
| 访谈、播客、日常双人交流 | 原生双人，保留连续轮次 | 只有确有倾听、附和、打断或重叠意图时才加 `|回应|`；普通问答可以没有回应标记 |
| 争辩、追问、抢话 | 两人时可用原生双人回应 | 长句、多次交错也可表达；位置是表演提示，不是毫秒时间轴 |
| 多人起哄、需独立调音或精确错开文件 | 分轨生成，再用 scenes 叠声 | 原生双人不承担三人以上群声；自定义声音或不兼容路由按实际能力选择逐轮制作 |

在阅读稿用一两句说明选择，局部例外标在该段。例如《孔乙己》整体是回忆叙事，掌柜与酒客的连续问答可考虑双人联合，酒客们高声起哄仍适合群声分轨；不能仅为了展示功能新增“嗯”“对啊”等原文没有的台词。

原文已有的回应可移入相应轮次的 `|...|`，并保留 source_text 供核对；新增回应属于改编。标签 `<sigh>` 表示当前台词位置的人声动作，`|回应|` 表示另一位听者的内容，两者不混用。需要听者声音时在阅读稿明确是谁回应，不能只显示一条没有说话人关系的竖线。

## 从戏剧意图到请求

分别保留：原文、实际说出的台词、稳定角色音色、这一轮的表演、瞬时事件。先选一个声音读真实台词，再根据用户反馈改变一个主要因素。脚本不会选择、评价或伪造试听结论。

例如“你终于回来了”：想表现释然，可以安排开头的一次轻叹，style 写“长时间等待后终于放松，音量低，避免责备”，无需额外添加“唉”。想表现失望，应调整表演意图，不能仅用提高音量代替。

- 身份：预置音色或该路由可用的存储式 voice ID。相同角色固定绑定，别每句随机换声音。
- 持续表演：疲惫、耳语、压抑的兴奋、语速、音量放进 style，自由描述而非固定枚举。
- 瞬时事件：用 events 放置叹气、吸气、笑声、停顿；偏移基于未插入标签的台词。事件不改变 source_text。
- 阅读稿中分别呈现“语气”和“动作”：语气说明持续表演，动作写明谁在什么词句前后做什么。动作同步为制作稿中的 events，并确认 style 没有相反要求。无需每段都加动作；不把每处文字提到的笑哭都演成声音，也不把页面上的中文说明当成台词或标签传入。
- 使用当前脚本与所选模型实际支持的标签。用户界面出现的 Expression 不代表当前接入商或脚本均已支持；不能猜标签。修订动作后保留旧录音及其实际请求，标明旧试听尚未体现新稿，不自动付费重录。
- 文本中的尖括号或 `|` 可能与模型控制语法冲突。先判断是要朗读符号还是控制表演，不自动吞掉或替换。
- 需要“嗯”“唉”等可读词语时视为台词编辑，保留原文并遵循用户授权。不要把角色名、场记、剧情说明混入待读台词。

## 路由与模型差异

Gemini 3.8 使用分离的 style 与事件。Google 原生、OpenRouter、AIHubMix 使用不同请求字段，由脚本映射。AIHubMix 文档当前示例为 2.5，instructions 可用不等于 3.8 标签必然可用；别为了使用标签擅自换供应商。旧模型的 prompt 风格有被朗读的风险，试听时注意。

按判断选 [JSON 双人表演或场景编排](arrangement.md)：原生双人将多轮及回应放进一个 clip，生成连贯表演；逐轮模式每轮一个 voice、一条 WAV，便于局部返工；群声分别生成再本地叠声。连续同角色长句尽量作为完整表演单元，不按每个标点过度切割。接入商长度限制要求拆分时在语义边界拆分。

Gemini 3.8 的 style 用短而具体的表演提示，不重复长角色履历，不写“保持同一音色”等元指令；声音身份由 voice 决定。给用户看的导演分析可以更详细，不要整段照搬到每条 TTS 请求。

## 迭代与交付

用户说“最后一句别那么用力”时，只改该片段 style，保留角色音色和台词。生成一个新候选，用户或具备听音能力的宿主决定选片。重做范围是整个 clip；原生双人 clip 包含双方的所有轮次与回应，不能单独修补其中一个人的一句话。

文件验证只能发现格式或截断问题，不能检查漏词、串词、情绪质量。可调用用户已有的审听工具，但不要暗中接入新的评审模型。没有听音能力时明确请求用户试听具体片段；不要把“API 成功”写成“情感自然”。

不保证精确停顿秒数、固定随机种子、逐字时码或声音身份绝对一致。时间线记录真实分轨与场景边界，可包含叠声。当前脚本不创建、复制或删除声音；相关需求保留在 PRD，不能用合成录音代替真人同意。
